## Part 2. The nightly job (build it on top of that commit, on its own branch, `feat/people-nightly-pull`)
**Behaviour (keep it small; copy the patterns of `run_people_refresh_job` and its scheduler block):**
- **Job:** `run_people_pull_job(config)` in `src/ddp_sync/pipelines/openstates_scrape.py`. It runs `git -C <root>/people pull --ff-only` where `<root>` is what `_get_root(config)` returns (the same folder `run-people-refresh.sh` pulls: `$SCRIPT_DIR/people`), through the same `_run_with_group_kill` helper, with a 300-second timeout. **No RDS, no `os-people`, no import**: pull only. (The weekly import stays as it is.)
- **Guards:** if `ddp:flow:openstates_people_refresh` shows `running` (the Sunday import, about 11 minutes), do not pull: write status `skipped` with the reason. Never use `--rebase`, `--force`, `reset` or `checkout`: a diverged local branch must **fail**, not be overwritten.
- **Flow status:** write `ddp:flow:openstates_people_pull` with `status` (`completed` / `failed` / `skipped`), `started_at`, `completed_at`, `duration_seconds`, `error` on failure, and, always, **`path`** (the folder pulled), **`head_sha`**, **`head_commit_date`** (`git -C ... log -1 --format=%h` and `%cI`), the **current branch**, and **what `git pull` said** (`Already up to date` or the summary line). Recording the path and HEAD date is the point: it is what would have shown, in July, that nothing was changing.
- **Failure must be visible the way other jobs' failures are** (the `failed` flow status that OPEN-286's alerting reads; confirm that is how a failed `people_refresh` surfaces, and say if it is not).
- **Schedule:** a new `people_pull` block in `config/sync_schedule.yaml` (`enabled: true`, `sync_time_utc: "03:00"`, daily) and a registration in `scheduler.py` next to the `people_refresh` one: `CronTrigger(hour=3, minute=0, timezone=_UTC)`, `id="openstates_people_pull"`, `name="OpenStates: people pull (nightly)"`, `replace_existing=True`, `max_instances=1`, `coalesce=True`, `misfire_grace_time=3600`, and a `logger.info("openstates_people_pull: registered", sync_time=...)`. 03:00 UTC is before the broker's roster step (04:00) and does not collide with `people_refresh` (Sunday 10:00).
- **Tests** in the style of `tests/test_scheduler_*.py`: the job is registered with that id and trigger; the job writes `completed` on a clean pull, `failed` on a non-zero exit or timeout, `skipped` while the weekly refresh is running; the git command is exactly `pull --ff-only` (no other flags). Run the repo's test command and report the counts.
- Commit on `feat/people-nightly-pull`, push, and **open a pull request to `main`** (title starts `SYNC:`, body says what Part 1 and this change are). **I will send it through `/pm-review`.** Do not merge it.
